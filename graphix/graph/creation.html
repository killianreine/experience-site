Créer un graphe

Le module graph::creation fournit la fonction build_graph, qui assemble un Graph<T> à partir de ses types, de ses sommets et de ses arêtes, en vérifiant que chaque arête relie des sommets existants.

Fichier : src/graph/creation.rs

build_graph​

src/graph/creation.rs
pub fn build_graph<T>(
    gt_: Vec<GraphType>,
    v_: Vec<Vertex<T>>,
    e_: Vec<Edge>,
) -> Graph<T>

Paramètres​

ParamètreTypeDescription
gt_Vec<GraphType>Propriétés du graphe (voir GraphType).
v_Vec<Vertex<T>>Sommets du graphe. Leur ordre fixe leurs indices : le premier a l'indice 0, etc.
e_Vec<Edge>Arêtes du graphe, dont les extrémités sont des indices dans v_.

Les trois vecteurs sont déplacés (move) dans le graphe : ils ne sont plus utilisables après l'appel.

Retour​

Un Graph<T> dont graph_type, vertex et edges sont respectivement gt_, v_ et e_.

Déroulement​

Glisser pour déplacer · Ctrl + molette pour zoomer

Erreurs​

La fonction panique (via assert!) si une arête désigne un sommet inexistant, avec un message du type :

arête Edge { source: 0, destination: 5, weight: 10 } invalide : le graphe n'a que 3 sommets
Pas de Result

build_graph ne renvoie pas de Result : une arête invalide interrompt le programme. Il faut donc s'assurer des indices avant l'appel si les données viennent d'une source externe (fichier, saisie…).

Ce qui n'est pas vérifié​

  • la cohérence de gt_ (ex. Default combiné à Oriented) ;
  • les doublons d'arêtes et les boucles, qui sont acceptés ;
  • l'unicité des id des sommets ;
  • le poids des arêtes d'un graphe non pondéré.

Exemple​

Un graphe orienté et pondéré de trois villes, avec les distances en kilomètres :

Glisser pour déplacer · Ctrl + molette pour zoomer
src/main.rs
mod graph;
mod model;

use graph::creation::build_graph;
use model::edge::Edge;
use model::graph::GraphType;
use model::vertex::Vertex;

fn main() {
    let g = build_graph(
        vec![GraphType::Oriented, GraphType::Weighted],
        vec![
            Vertex::new("Paris"),     // indice 0
            Vertex::new("Lyon"),      // indice 1
            Vertex::new("Marseille"), // indice 2
        ],
        vec![
            Edge::new(0, 1, 465), // Paris -> Lyon
            Edge::new(1, 2, 315), // Lyon -> Marseille
            Edge::new(0, 2, 775), // Paris -> Marseille
        ],
    );

    println!("Types : {:?}", g.graph_type);
    println!("Orienté : {}", g.is(GraphType::Oriented));
    println!("Sommets :");
    for (i, v) in g.vertex.iter().enumerate() {
        println!("  [{}] {} (degré {})", i, v.id, g.degree(i));
    }
    println!("Arêtes :");
    for e in &g.edges {
        println!(
            "  {} -> {} (poids {})",
            g.vertex[e.source].id, g.vertex[e.destination].id, e.weight
        );
    }
}

Sortie de cargo run :

Types : [Oriented, Weighted]
Orienté : true
Sommets :
  [0] Paris (degré entrant 0, sortant 2)
  [1] Lyon (degré entrant 1, sortant 1)
  [2] Marseille (degré entrant 2, sortant 0)
Arêtes :
  Paris -> Lyon (poids 465)
  Lyon -> Marseille (poids 315)
  Paris -> Marseille (poids 775)

Le même graphe sans GraphType::Oriented donnerait des degrés simples : Paris 2, Lyon 2, Marseille 2.

Organisation du code​

Pour l'instant, Graphix est un projet Rust exécutable (src/main.rs) ; les modules sont déclarés avec mod dans main.rs et ne sont pas encore exposés sous forme de bibliothèque (lib.rs).

graphix/
├── Cargo.toml          # paquet « graphix », édition 2024, sans dépendance
└── src/
    ├── main.rs         # programme d'exemple
    ├── model/          # les modèles
    │   ├── mod.rs
    │   ├── vertex.rs   # Vertex<T>
    │   ├── edge.rs     # Edge
    │   └── graph.rs    # Graph<T>, GraphType, Degree
    └── graph/          # les opérations sur les graphes
        ├── mod.rs
        └── creation.rs # build_graph
